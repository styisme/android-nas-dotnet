# 开发环境约束说明

本文档说明本仓库的**实际开发条件**与**责任边界**。

它的作用是：**让外部能看清"我们做了什么、没条件做什么"**，而不是套用一套"有本地 IDE、有 CI、有真机"的标准模板。

> 不同仓库条件不同。本文件允许按实际情况**勾选**，不强迫所有项目都声称完成了全部流程。

---

## 一、开发环境（按实际勾选）

- [ ] 有本地 IDE / SDK，可本地编译
- [ ] 有本地 diff 工具，可逐行审阅
- [ ] 可跑 lint / 单元测试
- [ ] 走标准 PR 流程（fork → PR → review）
- [x] **仅靠云端 CI 编译（无本地工具链）**
- [x] **仅靠移动端 / 手表端开发**
- [x] **走直推 master（无 PR 流程）**

> 未勾选的条目，代表**本仓库物理上无法执行**，不是"忽略了"。
> 本项目全程在 Android 手机端（Pydroid 3 / Termux）通过 Python 脚本覆盖文件，并直接使用 MGit 推送代码。无任何 PC 端 IDE 参与。

### 测试

- [ ] **真机测试**（真实的物理设备）
- [ ] **模拟器测试**（无物理设备条件下）
- [x] **未测试**（见下方诚实声明）

> 未勾选的条目，代表**本仓库没有条件做**，不是"忘了做"。

## 三、诚实声明

**以下情况必须如实标注，不得美化：**

- 若本仓库**没有做过任何真机或模拟器测试**，请在此处明说：
  > 「本仓库的代码未经真机测试。CI 编译通过仅代表语法与依赖正确，不代表功能可用。使用前请自行评估风险。」

- 若某模块**敏感但未验证**，请在下方清单中标为 `⚠️ 未验证`。

- 若某功能**默认开启**（不符合"高危默认关"原则），请明说原因。
  > 本项目仅 HTTP 8080 端口默认开启，其余如 FTP、WebDAV、HTTPS、全盘模式、Root 保活均默认关闭。

## 四、敏感模块清单（按实际填写）

以下模块涉及安全、权限、数据销毁等高危操作。请按**实际验证状态**标注：

|---|---|

## 五、我们承认这不完美

形式化的 PR 流程、逐行代码审阅、本地静态分析，这些在部分仓库里**可能全部缺位**。

我们用「**披露 + 门禁（能做的部分）+ 默认关**」承担了**实质责任**，而不是假装做到了所有**形式责任**。

这是约束下的选择，不是对标准的否定。

---

## 六、给其他极限约束开发者的建议

如果你也在极端约束下开发（无本地工具链 / 移动端 / 手表端），这套最小责任清单供参考：

1. **诚实披露 AI 参与度**（不要美化比例）
2. **高危功能默认关闭**（代码层面）
3. **能做的门禁不绕过**（有 CI 就卡 CI，没有就靠人工）
4. **测试状态如实标注**（做了就勾，没做就写"未测试"）
5. **敏感模块清单公开**（让外部能核对你测过什么）

**五件事做到了，你就已经承担了人类责任。** 形式上像不像别人，不重要。
